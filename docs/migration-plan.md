# Modular Migration Plan

This repository currently runs from a generated bundle in app.js.

## Goal
Move gameplay and rendering logic into maintainable source modules under src/ while keeping behavior parity.

## Current status
- Added modular core primitives:
  - Event bus
  - State machine
  - Animation frame engine loop
  - Asset manager and centralized manifest
- Added asset validator script to detect missing file regressions.
- Asset validation now rejects invalid or 1×1 placeholder PNGs in the manifest.
- Assets are never generated by code. `assets/static/clouds2.png` and `assets/static/timer_bg.png` are static, visible placeholders; replace them by dropping final art in under the same filenames.
- Added automated tests for state transitions, level initialization, deterministic gameplay, timer expiration, and manifest image dimensions.
- `npm test` now runs the Node.js test suite.
- Extracted gameplay configuration and systems:
  - Levels config
  - Physics config
  - Collision system
  - Gameplay system with deterministic verification script

## Next migration steps
1. Build rendering adapters (SVG and UI) in dedicated modules.
2. Connect extracted gameplay system to the new rendering layer.
3. Replace direct index.html bundle reference with a build output generated from src/.
4. Keep app.js as fallback until parity is validated.

The live entry point still loads the bundled `app.js`; the extracted systems and new tests do not yet replace or drive the live UI. Preserve that bundle until the modular screens, controls, and outcomes have been validated against the current game.
